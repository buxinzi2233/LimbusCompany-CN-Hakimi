### 1.2 核心裁决结论

1. **唯一 1 处 L03 FATAL 是“旧基准版本漂移”导致的纯粹误报**：
   `tools/linter.py` 默认回退读取的本机 Steam 客户端目录停留在 2026-09-17（第十章上半），其中 `Log_NpcDefeated` 包含旧占位符 `{0} 처치 (피해 {1})`；而 2026-09-24 官方下半更新已将其简化为 `{0} 처치`。中文工作区已按最新源同步为 `击败了 {0}`。显式指定 0924 冻结源目录后，**该 FATAL 瞬时清零**。
2. **L05 不能认证为 100% 官方继承或自动豁免**：469 个问题字段均有韩文 L05，但错误类别及标签名签名仅匹配 **1253/1258**，完整标签 token 序列相同仅涉及 **1052** 条目标问题，未证实实机正常或崩溃嘎呜
3. **L04 输出存在选择偏差且包含控制标签**：21,839 个历史输出项均为 ASCII ID，但输出前过滤非 ASCII 候选，不能据此断言中文词条漏空格为零；`[CantIdentify]`、`[CantDuel]` 等控制标签不得批量中文化嘎呜
4. **六条 L03 频次差异仍不符合项目 1:1 规则**：不得以一般格式化函数可重复引用为由自动豁免，调用点实参与运行时安全性未经验证嘎呜
5. **历史问题尚不能收敛为少量真实瑕疵**：L06 为 5 条复合词误报候选、2 条 RoseWedge 待裁定及 7 条动词违规；L07 的 17 条单省略号仅 2 条位于 id=-1，另 7 条为引号/连点问题，不能把前 17 条整体排除；历史 L01/L02 未报错不等于全库语义无瑕疵嘎呜

## 2. Linter 运行机制与基准回退路径分析

### 2.1 韩文源目录绑定代码溯源

在 `tools/linter.py` 中，源目录处理逻辑如下：

```python
DEFAULT_STEAM_KR_DIR = (
    "/home/buxinzi/.local/share/Steam/steamapps/common/Limbus Company/"
    "LimbusCompany_Data/Assets/Resources_moved/Localize/kr"
)

# Linter.__init__
self.source_dir = config.source_dir
if self.source_dir and not Path(self.source_dir).is_dir():
    raise FileNotFoundError(f"原文目录不存在: {self.source_dir}")
if not self.source_dir and os.path.exists(DEFAULT_STEAM_KR_DIR):
    self.source_dir = DEFAULT_STEAM_KR_DIR
```

- **回退行为**：当 CLI 未传 `--source-dir` 时，Linter 优先探查宿主机是否存在 `DEFAULT_STEAM_KR_DIR`。
- **环境实况**：宿主机该目录真实存在，因此默认命令 `python3 tools/linter.py` **静默绑定到了本地 Steam 游戏安装目录**，而非仓库内版本受控的 `references/baseline-KR/` 或冻结快照。

### 2.2 本地 Steam 客户端的版本漂移证据

| 属性 | 本地 Steam 客户端目录 | 仓库冻结快照 (`part2-scope-20260924`) |
|---|---|---|
| **修改时间** | 2026-09-17 19:40:34 UTC+8 (第十章上半包) | 2026-09-24 14:53:06 UTC+8 (第十章下半冻结) |
| **文件数量** | 2,177 个 JSON | 2,277 个 JSON (含下半新增100个资源) |
| **`Log_NpcDefeated` 文本** | `"{0} 처치 (피해 {1})"` | `"{0} 처치"` |
| **工作区当前文本** | `"{0} 击败了"` -> `"击败了 {0}"` | `"击败了 {0}"` |

### 2.3 `Log_NpcDefeated` 经典案深度剖析

- **现象**：默认扫描报错 `[FATAL] RPGSystem/rpg-loc-ui-common-a1c10p1.json: ID Log_NpcDefeated: 占位符与韩文源不匹配! 遗漏占位符 ["1"]`。
- **根因**：月亮计划（Project Moon）在 0924 下半更新中修改了韩文日志模板，移除了伤害数值占位符 `{1}`，仅保留击败目标 `{0}`。汉化团队已根据 0924 新源调整为 `击败了 {0}`。但默认 Linter 却用 0917 的旧客户端文件进行比对，误判定丢失了 `{1}`。
- **验证结论**：显式指定 `--source-dir backups/part2-scope-20260924/source-kr` 后，L03 占位符比对与源文完全一致，FATAL 立即降为 0。
- **铁律警示**：**绝对不可为了“修复”该默认报错而将 `{1}` 重新加回 `Log_NpcDefeated`**。加回 `{1}` 会导致新版客户端调用时发生 `FormatException` 运行时异常！

##### L05 错误四大特征聚类

1. **教程换色连续声明未闭合（478 项，涉及 `TutorialRenewalDesc.json`）**：
   - *韩文原版*：`먼저 <color=#f8c200>조작 패널<color=#ebcaa2>을 확인해주세요...`
   - *中文译文*：`首先请确认<color=#f8c200>仪表盘<color=#ebcaa2>。您可以通过...`
   - *机制*：月亮计划在编写新手教程时，直接用 `<color=#ebcaa2>`（底色）切换覆盖上一段高亮色，不加 `</color>` 闭合，且段尾亦不闭合。历史严格检查计为 478 处 FATAL；目标 TMP 版本如何显示未经实机验证嘎呜
2. **FIFO 队列式闭合违反 LIFO 栈闭合（580 项，涉及 `BossRaid`、`exme`、`PanicInfo`、`Skills_Abnormality-a1c9p3`）**：
   - *韩文原版*：`<color=#ff6000><mark color=#ff000040><b><u>텍스트</color></mark></b></u>`
   - *中文译文*：`<color=#ff6000><mark color=#ff000040><b><u>文本</color></mark></b></u>`
   - *机制*：原厂开发者开标签顺序为 `color(1) -> mark(2) -> b(3) -> u(4)`，闭标签却按相同顺序闭合为 `/color(1) -> /mark(2) -> /b(3) -> /u(4)`（FIFO 顺序）。该顺序不符合项目 LIFO 门禁；实际渲染正常或崩溃均未验证嘎呜
3. **BGM 歌词单向行样式标签（164 项，涉及 `BgmLyrics/*.json`）**：
   - *韩文原版*：`<style="DKR_CP9_1">아라야는 기다리고 있지 않아.`
   - *中文译文*：`<style="DEN_CP9_1">阿赖耶没有在等待任何人。`
   - *机制*：历史歌词聚类计为 164 处 FATAL；不能以未经验证的 TMP 组件生命周期假说解释为安全，Cromer2 还有三条未匹配签名，不能统一放宽 `style` 嘎呜
4. **原厂畸形标签残留（36 项，涉及 `ChoiceEventEffect.json` 等）**：
   - *韩文原版*：`... <color=#80c9ff>정신력</color> </color=#ebcaa2>회복</color>`
   - *中文译文*：`... </color=#ebcaa2>恢复</color>`
   - *机制*：月亮计划原开发者误手写了 `</color=#ebcaa2>` 这种带属性的闭标签，汉化文件原样保留。
