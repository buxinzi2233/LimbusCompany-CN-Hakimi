# 都市零协会汉化规范调研报告（三）：战斗技能类文本翻译与排版规约

## 1. 调研背景与机制本质
《边狱公司》（Limbus Company）的战斗系统高度数字化与词条化。技能描述文本不仅是供玩家阅读的文学说明，更是游戏底层数值逻辑与 UI 交互的直观投影。翻译中的任何一字之差（如“层数”与“强度”混淆、动词颠倒）都会直接引发玩家对战斗机制的严重误判。本报告系统归纳零协会技能翻译的“四大铁律”与“语法定式”。

---

## 2. 核心规约：Buff/Debuff 三态动词铁律

在边狱公司的状态体系中，所有异常状态均包含两个核心维度：
- **强度（Potency）**：决定状态触发时的威力、伤害量或暴击率提升数值。
- **层数（Count）**：决定状态可被触发/维持的回合次数或消耗次数。

为了实现零歧义表达，零协会确立了严格的动词分工体系：

| 作用对象 | 状态性质 | 强制规范动词 | 正确范例 | 严禁使用的错误动词 |
| :--- | :--- | :--- | :--- | :--- |
| **层数 (Count)** | 正面状态 (Buff) | **获得** | `自身获得2层呼吸法次数` | 施加、赋予、得到、加上 |
| **层数 (Count)** | 负面状态 (Debuff) | **施加** | `对目标施加3层流血次数` | 获得、给予、附着、烙印 |
| **强度 (Potency)** | 正面 / 负面状态 | **增加** | `使目标的震颤强度增加3点` | 获得、施加、叠加、提升 |
| **数值减少/衰退** | 任意状态 | **减少** / **消耗** | `使自身的充能层数减少5点` | 降低、扣减、剥夺 |

> **法则总结**：
> - 层数论“得失”：对己是“获得”，对敌是“施加”。
> - 强度论“增减”：无论敌我正负，数值上升一律称“增加”，数值下降一律称“减少”。

## 3. 关键词空格后置与超链接触发机制

### 3.1 词条悬浮窗触发机制
Unity 端的富文本解析器通过正则表达式检测特定文本词条。为了准确触发 `BattleKeywords.json` 中的弹出说明卡片，**所有战斗关键字之后必须且只能紧跟一个英文半角空格**。

- **标准格式**：`[关键词] `（如：`震颤 `、`流血 `、`呼吸法 `、`充能 `、`沉沦 `、`破裂 `）
- **错误示范**：
  - `对目标施加震颤。`（缺少后置空格，无法激活高亮，不能弹出说明）
  - `对目标施加 震颤 `（前置多余空格，导致换行排版混乱）
  - `对目标施加震颤　`（误用了全角空格）

## 4. 技能条件状语与触发时机标准句式

技能描述中的时机判定采用固定中文中括号标头：

| 条件标识符 | 规范中文表述 | 逻辑触发点 |
| :--- | :--- | :--- |
| `[OnSucceedAttack]` | `[命中时]` | 硬币攻击命中且未被防御抵消 |
| `[OnWinDuel]` | `[拼点胜利]` | 拼点对抗中点数胜出 |
| `[OnLoseDuel]` | `[拼点失败]` | 拼点对抗中点数落败 |
| `[BeforeAttack]` / `[OnUse]` | `[使用时]` | 技能开始动作释放的瞬间（无论拼点） |
| `[OnCrit]` | `[暴击时]` | 攻击产生暴击伤害时 |
| `[Kill]` | `[击杀时]` | 攻击导致敌方生命值归零时 |
| `[RoundEnd]` | `[回合结束时]` | 当前战斗回合完全结算完毕阶段 |
| `[StartRound]` | `[回合开始时]` | 新一轮战斗行动排序阶段 |

## 5. 战斗数值与机制表达深度规约

### 5.1 混乱阈值（Stagger Threshold）
- **前移**：使敌人更容易进入混乱（`使目标的混乱阈值前移20点`）。
- **后移**：延迟敌人混乱。
- **禁忌**：阈值是刻度点，严禁添加不规范量词（如“前移20%”必须明确是百分比还是绝对数值）。

### 5.2 威力（Power）体系区分
- **基础威力（Base Power）**：技能或硬币未投掷时的原始起点。
- **硬币威力（Coin Power）**：每掷出一枚正面硬币所累加的点数（如：`硬币威力+2`）。
- **拼点威力（Clash Power）**：仅在拼点对抗时生效的额外加成（如：`拼点威力+1`）。
- **最终威力（Final Power）**：拼点计算完成后直接施加在结算总点数上的数值。

### 5.3 物理与罪孽抗性（Resistances）表达
- **抗性数值增加**（如：斩击抗性 1.0 -> 1.5）：在游戏中表示受到的斩击伤害增加，中文必须准确表述为：`斩击抗性增加` 或 `受到更多斩击伤害`，严禁产生“抗击打能力提升/减伤”的反向误解。
- **抗性数值减少**（如：打击抗性 1.0 -> 0.5）：表示更耐揍，表述为：`打击抗性减少`。

## 6. 排版与长度压缩规范
1. **半角括号**：技能条件与补充说明统一使用半角括号 `( )`，紧贴文字，不留冗余空格，避免在手机端或狭窄战斗框体内被折行截断。
2. **连接符**：范围数值统一使用半角波浪号 `~`（如：`造成12~18点物理伤害`）。
